# 新流程中心与业务接入

状态：实现完成，本地验收通过，最终提交后由 CI 复验（2026-10-04）。

## 目标与复用决策

普通用户从业务表单提交申请，审批人在待办中办理，业务状态随流程结果更新，全程不需要填写定义 ID 或实例 ID。

用户确认可视化设计器优先参考 RuoYi-Vue-Plus 并复用成熟组件。RuoYi-Vue-Plus 5.X 的父 POM 使用 Warm-Flow 1.8.9，并管理 `warm-flow-plugin-ui-sb-web`；nz-admin 当前引擎版本也是 1.8.9。优先采用同版本官方设计器，沿用 RuoYi 的集成方式，不继续扩展自绘 SVG 画布。

上游参考：

- [RuoYi-Vue-Plus 5.X 依赖](https://github.com/dromara/RuoYi-Vue-Plus/blob/5.X/pom.xml)
- [RuoYi 工作流模块](https://github.com/dromara/RuoYi-Vue-Plus/tree/5.X/ruoyi-modules/ruoyi-workflow)
- [Warm-Flow 官方源码](https://github.com/dromara/warm-flow)

版本固定在当前兼容版本。集成前核对官方设计器资源、前后端交互协议和分发许可，保留相关开源声明。

## 实施顺序

1. 接入官方设计器及流程定义列表，支持创建、设计、保存、发布和查看版本；使用真实浏览器验收拖拽与保存后重载。
2. 新引擎流程中心提供我的申请、我的待办、我的已办、实例详情及审批轨迹，以列表导航替代内部 ID 输入。
3. 请假申请示例贯通保存草稿、提交、审批通过/退回和业务状态同步。定义通用业务接入接口，处理重复提交与回调失败重试。
4. 逐步补齐新引擎撤回、终止、转办、委派、指定节点退回与加减签，并验证双节点运行。

## 集成边界

设计器和引擎复用上游；业务接入、租户、权限、幂等与模块装配适配 nz-admin 的现有约定。工作流模块保持不依赖 system 业务模块，通过现有办理人解析协议接入用户和角色。

同版本 UI 插件中的标准控制器包含直接保存完整 DefJson 的入口。接入时必须明确其鉴权与字段边界，保留当前实例参与人权限、字符串租户过滤、服务端审计字段和受控模型校验；不能只把画布加载成功作为验收完成。

存量模型与在途实例继续走 legacy；新设计器写入新引擎定义，发布新版本不改写在途实例。

## 第一轮验收

- 从定义列表进入官方设计器，拖拽节点/连线、选择当前租户办理人、保存并重新打开。
- 普通用户提交请假；审批人从待办进入办理；业务状态与审批轨迹正确更新。
- 禁止跨租户定义访问、非办理人操作和不受控表达式/监听器配置。
- 并发与网络重试不重复启动审批或重复更新业务状态。
- 后端权限/事务测试及浏览器完整链路通过。

## 实施结论

- 接入 Warm-Flow 1.8.9 官方经典 UI 静态资源，移除自绘 SVG 编辑器；保存接口保持设计权限、租户身份和字段白名单。办理人回显兼容上游带索引数组参数。保留 Apache-2.0 许可与 NOTICE。
- 流程中心提供待办、申请、已办、业务快照、历史轨迹和管理操作。定义用途在管理员设计入口设置；请假只能选择本用途的发布流程。
- 业务 SPI 与模块实现解耦，业务键锁防止不同请求键重复启动；数据库事件与引擎事务提交，多节点竞争投递，失败回滚重试，处理器按实例/序号幂等。
- 指定节点退回只允许已访问的审批节点；无退回连线时结束当前实例交还业务，重新提交创建新实例，原业务快照与轨迹继续保留。撤回使用原生结束操作，避免上游 revoke 重新生成审批任务。
- 数据库锁串行化同租户/编码的定义版本、发布和启动；实例锁保护审批操作。修复实时连接错误被全局处理为 HTTP 200，以及退出后令牌租户恢复误报 503 的问题。
- 浏览器 fixture 按 worker 登录一次，每个用例仍使用独立上下文，避免套件增长触发生产登录频控。新增请假日期回填、退回后修改、重新提交和原快照保护验收。

## 验收证据

- 后端完整测试 274 个通过，使用独立 PostgreSQL 16 与 Redis；覆盖 V1–V30 迁移、实际 HTTP 权限、设计器协议、回调故障重试和高级流程操作。
- 前端 104 个测试、类型检查与生产构建通过；控制台 Chromium 共 6 个用例通过，包含设计器拖拽/选人/保存/重载/发布和普通用户请假审批闭环。
- 两个实际 Java 后端进程共享 PostgreSQL/Redis：并发版本唯一且只有一个发布版；不同请求键只启动一次；相同请求键跨节点审批一次；SSE 消息、票据一次消费、退出关闭连接及会话撤销通过。脚本为 `tools/tests/workflow-cluster.mjs`。
- 27 个 CLI 测试、V30 迁移检查和交付配置检查通过。CI 增加第二后端节点与双节点验证。

## 升级与边界

执行 V30（或对应 P30 手工升级），开启 `NZ_WARM_FLOW_ENABLED=true`；集群模式还需要共享 PostgreSQL、Redis 和相同状态前缀。只开放经典模型，未接入仿钉钉模型或通用表单设计器，不开放任意监听器/执行表达式。外部副作用仍需接收方幂等，Redis Pub/Sub 不替代离线可靠消息。

CI 首次验证发现拖拽不会在所有环境中附带节点点击，设计器验收改为明确打开属性面板后选人。租户默认登记补入请假与流程业务事件表，确保关闭可选模块时仍能识别保留的表；模块启用后继续由各自隔离配置管理。
