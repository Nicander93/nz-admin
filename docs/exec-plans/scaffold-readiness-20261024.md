# 系统功能稳定性收敛与回归验收

基线：497d01e，2026-10-24。保留用户已有 tsbuildinfo、.serena 与根 package-lock。

## 本轮目标

1. 修复禁用角色/菜单仍授权；统一当前有效角色、功能权限和菜单来源，保留隐藏菜单与禁用菜单的区别。补数据库与真实 HTTP 撤权回归，验证已有会话也即时失权。
2. 任务请求采用字段白名单与校验，租户归属由服务端决定，修改不迁移租户。任务执行限定明确声明的方法。
3. 调度启动恢复独立于基础数据初始化；生产 initialize-data=false 时可恢复启用且未过期租户任务，注册失败不伪装成功。补真实 Scheduler 和 PostgreSQL HTTP 回归。
4. 为核心管理补浏览器闭环：用户/角色/菜单授权撤销、租户隔离、数据范围。保留真实后端，不用浏览器 mock 替代拒绝行为。
5. 本轮以现有功能稳定性为边界，完成安全、生命周期和核心管理回归；新模块黄金路径另行验收。
6. 更新开发者文档、源码目录与 CI。执行聚焦回归后再做完整测试、构建与真实浏览器/双节点验证，最后只提交本轮文件。

## 实施约束

- 框架和 job 不反向依赖 system；租户枚举使用公共轻协议，由 system 实现。
- 暂不引入调度中心、动态数据源或新低代码平台。单节点任务恢复不等于集群全局唯一执行。
- 自动化用例断言实际数据、权限与生命周期，不只检查 HTTP 成功或按钮可见。
- 不以测试总数代替覆盖率；CI 外部依赖测试要明确开启并检查 skip。

## 实际发现与修复

- 授权统一过滤禁用角色和禁用菜单，隐藏与停用分离，目录不产生功能权限。
- 任务 DTO 白名单、可信租户归属、对象不存在/越权拒绝；手动执行与定时触发均重验租户有效性。
- `@JobTask` 限定可调用方法；补齐执行事件/日志的任务 ID、名称、分组，修复任务方法成功但日志插入失败。
- 独立 Runner 恢复调度，分页读取有效租户任务；真实关闭/重建应用验证恢复。调度失败会让写入失败并回滚，补偿恢复仍可能因调度器故障失败，此时明确记录恢复和重启要求。
- 修复用户/角色/公告/字典保存成功不关闭、不刷新；保存与删除都区分业务失败和刷新失败。权限树限制滚动高度，确认按钮可达。
- 修复无菜单或仅关闭模块/未知组件菜单的登录循环，落到 `/profile`。
- H2 壳层测试显式使用空租户任务提供器，完整调度在真实 PostgreSQL 上验证；工作流测试复用真实会话，显式注销后清除对应会话缓存，不关闭防重/限流来迁就测试。

## 保留边界

自动化覆盖了以上关键链路，不等同全部功能完备或覆盖率达标。Quartz 仍未提供多节点全局唯一执行保证；数据库回滚后的调度补偿在 Scheduler 不可用时可能失败，必须修复服务并重启恢复。升级前应为已有自定义任务补 `@JobTask`；直接扩展执行器时需改用携带正数任务 ID 的 `JobInvocation`。
