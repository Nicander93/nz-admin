# 脚手架可靠性与能力补齐

目标：修复真实环境失败，保证生成业务遵循隔离规则，补齐共享状态与工作流迁移验证。

## 验收顺序

1. Node 22.13 加载测试包；真实 PostgreSQL 权限测试；浏览器冒烟实际执行。
2. 原子防重、按请求内容识别、清理过期键；独立业务幂等协议与并发回归。
3. 生成器配置租户与归属、生成过滤注册和服务端归属赋值；验证生成代码可编译。
4. 按功能权限计算角色范围、归属变更校验与新表接入检查。
5. Redis 共享会话、接口保护、验证码、授权 state、实时票据与消息；跨实例验证。
6. 工作流运行时迁移边界、存量兼容和新引擎权限验收。
7. 新库/升级、生成业务、备份恢复与文档一致性验证。

## 约束

保留既有未提交改动；真实数据库测试只使用独立测试库。框架不依赖业务模块，迁移只向前。

## 进展

初始基线：本地单测通过，但 CI Node 22.13 无法直接加载测试配置中的 TypeScript；真实 PostgreSQL 权限拒绝错误返回 HTTP 500。

本轮实现完成（2026-10-03）：

- 测试配置改为 ESM JavaScript 与类型声明；补齐全局异常处理、按钮权限切面自动装配及认证/租户过滤器顺序。
- 防重与限流采用原子状态；请求内容按稳定 JSON 计算摘要。新增 PostgreSQL 幂等事务协议，覆盖成功重放、并发、冲突、失败回滚和过期后复用。
- 生成器支持租户/部门/所有者配置，输出隔离规则和接入说明，创建时从登录上下文赋归属，更新 DTO 排除归属字段。实际生成 Java 代码经过编译验证。
- 数据范围按当前功能权限筛选角色，再计算并集。新增租户表接入审计，真实 HTTP 验证跨租户拒绝、无关全量角色和自定义部门配置。
- 显式集群模式共享会话、保护状态、验证码、OAuth state、实时票据及撤销版本；Redis Pub/Sub 转发实时消息和退出。两组独立客户端验证原子竞争与跨节点消费。
- 新工作流入口启用 Warm-Flow，提供声明式模型图形编辑、导入/读取/发布、发起、审批和轨迹。字符串租户过滤保护标准表；只接受用户/角色办理人和内置比较条件。存量实例仍走 legacy；V29 向前补齐实际 ORM 字段。
- 迁移检查同时验证资源登记、手工升级脚本和 README 版本；模块生成自动同步版本。完成独立测试库备份恢复演练。

应用集成测试按类隔离 JVM：Warm-Flow 1.8.9 的 Spring 静态上下文只保留首次绑定，无法在同进程切换多个应用数据源。流程测试保留真实登录限流，只在用例之间清理测试专属限流键。

浏览器实际验收修复了两处原有/新增测试的重复文本定位，以及模型编辑器节点编码输入丢失问题。

## 交付边界

- 新增迁移 V27、V28、V29；已导入的数据权限改动需要 V26。生产升级至 V29，新引擎通过 `NZ_WARM_FLOW_ENABLED=true` 显式开启。
- 多节点需要共享 PostgreSQL、Redis 和一致的键前缀，开启 cluster 与 Redis readiness。Pub/Sub 不保证离线投递，当前在线统计仍是单节点指标。
- 幂等保证同一数据源内的事务效果；外部支付/HTTP/消息需要对方幂等协议或 outbox。过期记录通过 `IdempotencyExecutor.purgeExpired()` 接入定期清理任务。
- 本机 Docker daemon 不可用，未本地构建交付镜像；已有 CI delivery job 负责镜像构建。此处本地通过不代表远端 CI 已通过。
- 新引擎暂未交付自由拖拽画布、加减签、任意节点退回、业务回调协议和全局流程监控；不能据此宣称与成熟流程产品功能完全对齐。详见 `docs/workflow.md`。
