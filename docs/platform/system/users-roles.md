# 用户、部门、岗位与角色

部门表达组织归属，岗位表达人员职位，角色表达授权。给用户分配岗位，不会自动获得同名角色的权限；给角色分配菜单，也不自动决定所有数据可见。

## 建立一个普通业务账号

1. 在部门管理中建立组织树，确认上级和启用状态。
2. 按需要建立岗位，岗位编码与名称保持稳定。
3. 建立角色，分配业务菜单及所需按钮，不直接复制管理员全部权限。
4. 配置角色数据范围：本人、本部门、本部门及下级、自定义部门或全部。
5. 创建用户，选择部门、岗位和启用角色。
6. 使用独立会话登录，检查实际菜单和数据。

部门树影响“本部门及下级”范围。移动组织或修改用户部门后，不能只检查用户列表显示，还应检查原有数据是否仍符合业务归属规则。

## 多角色如何生效

菜单与按钮由启用角色授权，同时受租户套餐限制。数据范围在带功能权限的 HTTP 入口只合并拥有该功能权限的启用角色，防止另一报表角色的全部范围扩大当前编辑权限。

例如“查询角色”有全量查询范围，“编辑角色”只有本人范围：查询可以看到更多记录，编辑不能因此获得全部范围。是否可修改仍由该接口对应的功能上下文与业务状态检查决定。

## 停用、改密和退出

停用用户或角色后，用真实请求核对不可用状态。密码重置应使用专门操作，不把密码字段混入普通用户更新 DTO。需要立即撤销当前会话时，使用在线用户强制退出，并核对实时连接关闭。

用户名不是数据权限绕过条件，名为 admin 的普通账号也不能获得隐式全量访问。全量访问来自明确角色范围与功能授权。

## 授权结果不符合预期

| 现象 | 检查 |
| --- | --- |
| 没有业务菜单 | 模块、租户套餐、启用角色菜单 |
| 有菜单无按钮 | 对应按钮权限字符串 |
| 有权限无记录 | 用户部门、记录归属、角色数据范围 |
| 自定义部门范围为空 | 是否实际保存部门集合 |
| 另一个租户账号查到记录 | 立即检查表登记或 JDBC 显式条件 |
