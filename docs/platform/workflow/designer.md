# 官方设计器与流程版本

管理员设计的是可发布的流程定义；运行中的实例绑定具体版本。修改新版本，不改写已提交申请的审批轨迹。

## 创建到发布

1. 在流程中心进入定义管理，需要 `workflow:engine:design`。
2. 创建定义，填写流程编码、名称和业务用途。
3. 进入经典画布，拖拽节点、连线并设置办理人。
4. 保存草稿，离开后重新打开，核对结构、坐标、连线和办理人。
5. 发布后使用普通用户完成一次业务测试。

新建三节点默认流程的审批人是当前设计人员，不能直接视为最终业务配置。请假用途必须明确选择“请假申请”；通用流程不会出现在请假可选列表中。

## 办理人与比例

办理人选择器只提供当前租户的有效用户与角色。内部表达使用 `user:<id>`、`role:<roleKey>`，适配层处理官方 UI 的分隔协议，不让用户手工拼接跨租户 ID。

| nodeRatio | 行为 |
| --- | --- |
| 0 | 或签 |
| 100 | 会签 |
| 中间值 | 按比例通过 |

发布前用真实用户验证角色办理与多人审批，不只检查画布属性文字。条件仅开放内置比较，不接入任意脚本或监听器。

## 版本管理

未发布、未被实例引用的草稿可以编辑。已发布或历史定义通过“创建新版本”修改；同租户同编码的创建、保存、发布和启动由数据库锁串行化，发布只保留一个当前版本。

业务用途对同一编码保持稳定，新版本继承用途；更换业务用途应建立独立编码，避免已有业务与历史版本混淆。

## 安全与模型边界

UI 静态资源来自 Warm-Flow 1.8.9，不装配上游通用保存控制器。保存经过设计权限、租户校验和字段白名单；不接受客户端审计字段、监听器或仿钉钉模型。

认证来自同源存储与请求头，不放在 URL。宿主页只接受当前同源 iframe 的消息。旧模型缺少坐标时由服务端补齐，不能把静态资源可访问当成设计 API 已授权。

发布或保存失败的排查见[工作流排错](/platform/workflow/troubleshooting)，开发协议见[技术手册](/workflow)。
