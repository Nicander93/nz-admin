# 审批中心与请假申请

申请人操作业务单据，审批人操作待办任务。流程中心把两类操作的状态、业务快照和轨迹放在可访问的列表中。

## 申请人提交

管理员先发布请假用途流程。申请人在“示例模块 → 请假申请”填写原因、开始/结束日期和可选流程，保存草稿后提交。日期保持纯日期格式，结束不能早于开始，跨度受服务端约束。

只能读写本人的单据；审批中不能修改。重复提交已有在途申请返回当前实例，不会因为页面连点再开一条审批。流程选项为空时检查用途和发布状态，不要手工填定义 ID 绕过选择。

## 审批人办理

从“我的待办”进入，先阅读审批快照，再同意或退回并填写意见。详情需要实例参与人身份；有 query 权限也不能查看任意人的实例。

| 操作 | 要理解的行为 |
| --- | --- |
| 转办 | 改由其他有效办理人处理，保留轨迹 |
| 委派 | 受托完成后归还原办理人，不代表最终通过 |
| 指定节点退回 | 只能选择本实例已经到达的审批节点 |
| 加减签 | 遵循当前节点比例，减签至少保留一人 |
| 撤回 | 申请人结束当前审批，保留历史 |
| 终止 | 结束在途审批，单据按业务回调规则更新 |

## 退回后再提交

有 REJECT 连线时按连线退回；没有退回连线时结束当前实例，让业务恢复可编辑状态。修改后重新提交创建新实例；旧轨迹与业务快照不覆盖。请假被退回后继续使用原流程编码，更换流程应新建申请。

“我的申请”和“我的已办”可以读取自己参与的历史，不代表用户获得全局流程监控权限。

## 状态同步不是浏览器直接改值

引擎操作与事件在数据库事务中提交，业务回调随后投递。详情提示“正在同步”或“待重试”时会自动刷新，不应再次提交相反操作去纠正界面。

开发者需要定义业务状态映射，见[业务接入](/platform/workflow/business-integration)。长时间未同步时按[排错步骤](/platform/workflow/troubleshooting)检查事件，不直接修改任务表。
