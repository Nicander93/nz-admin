# 角色范围与业务表接入

数据权限只解决同租户内“哪些记录可操作”，接口权限解决“能否执行此功能”。新增业务两者都接入。

## 五种范围

| 范围 | 适用记录 |
| --- | --- |
| 全部 | 当前租户与当前功能范围内的全部 |
| 自定义部门 | 角色保存的部门集合 |
| 本部门 | 当前用户部门 |
| 本部门及下级 | 从当前用户部门展开组织树 |
| 仅本人 | 当前用户 ID 匹配归属字段 |

新角色默认仅本人。无启用角色或自定义部门集合为空，不自动扩大范围。带 SaCheckPermission 的 HTTP 功能入口只合并拥有相应权限的启用角色；未标记功能的内部调用仍按现有角色并集机制处理。

## 注册一张表

```java
@Bean
public DataScopeRuleCustomizer orderDataScopeRules() {
    return rules -> rules.add(new DataScopeRule("biz_order", "dept_id", "owner_id"));
}
```

类型来自 `com.nz.admin.framework.datascope.core`；表名、部门列、归属列要与真实 schema 一致。不支持某个维度时传 null，至少提供一个归属维度。没有部门列的表不能因用户拥有部门范围就匹配任意记录。

## 查询与写入

注册后的 MyBatis 查询、详情、更新和删除共享 SQL AST 过滤，分页在过滤后执行。INSERT 与归属调整仍由 Service 校验；客户端不能自己指定 owner_id 获取不属于它的记录。

JDBC、其他数据源、主动绕过插件的查询不在自动过滤范围内。导出和批量删除也要检查真实生成的条件，不能只测分页列表。

## 内部绕过应保持最小范围

认证解析等内部需求可使用 `DataScopeContext.withoutFilter`，它不跳过租户隔离。不能把绕过开关暴露成请求参数，也不能靠绕过实现普通管理员操作。

## 最小权限测试

创建不同部门与归属的记录；给用户配置本人角色、部门角色、无关功能全量角色，分别验证当前功能的列表、详情、更新和删除。再跨租户验证不可见。历史无归属数据上线前按业务回填，不用增加全量角色解决。

完整接口边界和升级说明见[数据权限手册](/data-permission)，实际 HTTP 验证见[后端测试](/guide/testing/backend)。
