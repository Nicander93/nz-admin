# 账号、租户变化后的会话失效

用户停用、修改密码或租户到期后，只阻止下一次登录还不够。已经登录的令牌、尚未消费的实时票据和已经建立的连接都必须重新核对身份。

## 用数据库版本固定登录身份

V32 给 `sys_user` 和 `sys_tenant` 增加 `auth_version`。用户的密码、状态、用户名或手机号凭据变化时，用户版本随业务写入原子递增；租户状态、到期时间或套餐切换时，租户版本随事务递增。只改昵称、邮箱等普通资料不增加版本。事务回滚时版本一起回滚，不会误撤销已有会话。

每次登录生成独立令牌，并把用户/租户 ID 和当时的版本写进服务端 Token Session。受保护请求通过 `IdentityValidator` 同时核对用户存在且启用、所属租户启用且未过期、两个版本一致。客户端不能指定版本；租户由可信会话确定。

重新启用用户、续期租户或重新登录都不会改写旧令牌中的版本，因此旧令牌不能复活。套餐内容修改仍实时影响功能权限交集；切换租户所属套餐会使旧身份版本失效。

## 覆盖实时连接

一次性票据携带同一个 `IdentitySnapshot`。消费票据和建立连接时重新核对身份，消息实际投递前也会核对。已有 SSE/WebSocket 连接按默认 1000 毫秒间隔复查身份，使租户自然到期时也能关闭连接；该间隔是轮询配置，不代表外部数据库故障时的硬实时上限。

旧版本连接失效只关闭该版本的连接，不误伤重新登录后的新版本连接。显式退出或管理员强制退出继续使用现有票据撤销和跨节点断连协议。

## 失败与升级行为

- 失效身份返回业务码 `401`，需要重新登录。
- 身份存储不可用或未配置校验器时拒绝受保护请求，返回 `503`，不降级成默认租户或跳过验证。
- 实时连接无法核对身份时关闭，恢复后重新获取票据。
- 部署前执行 V32 迁移；升级前没有版本的会话需要重新登录。滚动部署须避免旧版本节点继续签发不带版本的会话，先停止旧节点接流量，再开放新版本。

`IdentityValidator` 位于 `nz-common-core`，auth 和 realtime 通过该轻协议校验身份，system 实现数据库边界。替换账户系统时必须提供该实现，不能只实现显示用户名的 `AuthUserResolver`。

## 浏览器状态与恢复

失效响应同时清理令牌、Pinia 身份、权限、菜单和本次动态路由，避免重新登录后沿用上一账户。其他标签注销时同步回登录页；其他标签切换令牌时重载身份。旧请求返回的成功数据或迟到的 401 都不能覆盖、注销新身份。

首次加载账户信息遇到临时故障时保留令牌并显示重试页，不把 503 当成注销。用户可以重试恢复，也可以主动重新登录。改密或登录手机号变更成功后明确提示重新登录，不再用已失效令牌刷新资料。
