# 能力测试矩阵

这份矩阵回答两个不同问题：仓库里有哪些测试源码，以及这些测试在哪种真实环境中实际运行过。源码存在、CI job 通过、连接真实服务验证是不同证据；单测数量不代表业务覆盖率。本文不估算覆盖率百分比。

## 证据范围

- **CI 基线**：提交 `0e5940a` 的 [六个 CI job 运行记录](https://github.com/Nicander93/nz-admin/actions/runs/40152763941)。该记录只证明这个提交上的流水线结果，不代表后续未提交改动已通过。
- **本地真实环境**：本轮账号生命周期和文件生命周期已在本地 PostgreSQL 与真实浏览器路径验证。它们不等于 OAuth、对象存储等外部服务的实测。
- **源码存在，待验收**：可以在仓库找到对应测试，但当前没有本轮真实环境运行结果，不能据此声称已通过。

## 升级验收时如何更新

新增或改变一个业务能力时，按实际证据更新对应行：

1. 链接到具体测试源码，标明是单测、模块集成、真实 PostgreSQL HTTP、浏览器或多节点测试。
2. 只记录能从 CI 记录或本地运行日志复核的环境与结果；mock、内存实现和测试容器要明确写出。
3. 将尚未执行的外部服务、灾备、负载或浏览器路径保留在“仍需补充”列。
4. 不以测试文件数量、通过率或构建成功推断业务覆盖率。
