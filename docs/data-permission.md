# 数据权限接入

数据权限决定当前用户能操作哪些记录；菜单权限仍决定能否调用接口。两者同时生效，租户隔离继续独立执行。

## 角色范围

用户直接关联部门，角色配置数据范围。只合并启用角色，多个角色取并集。

| 值 | 范围 | 来源 |
| --- | --- | --- |
| 1 | 全部数据 | 当前租户内的全部记录 |
| 2 | 自定义部门 | `sys_role_dept` 中的部门集合 |
| 3 | 本部门 | 当前用户的 `dept_id` |
| 4 | 本部门及下级 | 从当前用户部门展开部门树 |
| 5 | 仅本人 | 当前用户 ID 与表的归属字段匹配 |

新角色默认仅本人。没有启用角色时范围为空；缺失登录身份、用户不可用或配置非法时拒绝访问。全部数据依赖显式角色配置，不根据用户名或角色名称绕过。

## 注册业务表

业务模块依赖 `nz-starter-datascope`，注册 `DataScopeRuleCustomizer` Bean：

```java
@Bean
public DataScopeRuleCustomizer orderDataScopeRules() {
    return rules -> rules.add(new DataScopeRule("biz_order", "dept_id", "owner_id"));
}
```

字段参数依次是表名、部门字段、用户归属字段；不支持的维度传 `null`。至少提供一个归属字段，标识符只允许简单 SQL 标识符。

框架通过 MyBatis-Plus `DataPermissionInterceptor` 为已注册表构造 SQL AST 条件。查询、详情、更新和删除共享规则，分页在过滤之后执行；无需给每个 Mapper 方法加注解。未注册表不会自动受保护。新增表必须明确决定是否接入。

`sys_user` 使用 `dept_id` 和 `id`；`demo_item` 使用 `owner_id`，新增记录从登录上下文写入归属。demo 没有部门维度，因此仅有部门范围的角色不能访问 demo 记录，需要本人或全部范围。

INSERT 不靠行过滤判断。创建、修改归属字段须由业务服务校验：用户服务验证目标部门，demo 服务固定创建人，禁止由客户端指定归属。复杂 JOIN、子查询及批量 SQL 新增时应补集成测试；直接 JDBC、其他数据源及手动忽略 MyBatis 插件不在此机制内。

## 内部查询

认证解析、数据范围解析、个人中心和初始化存在内部访问需求，使用 `DataScopeContext.withoutFilter(() -> ...)` 包裹最小范围操作。它只跳过数据范围，仍保留租户条件，并在异常和嵌套调用后恢复状态。不能向请求暴露绕过开关；异步任务不能假定继承登录或绕过上下文。

个人中心的目标用户由认证接口固定，不能接收任意用户 ID。内部绕过不是通用管理员授权接口。

## 升级

执行 Flyway V26（手动升级对应 `upgrade-p26-data-scope.sql`），新增角色部门关系和 demo 归属字段。只有原来为空的数据范围会回填：内置 admin 为全部，其余为仅本人。已配置范围保留。

历史 demo 的 `owner_id` 为空，只对全部范围可见；上线前按实际业务归属回填。历史自定义部门角色需在角色页面重新配置部门，未配置时范围为空。

带功能权限的 HTTP 入口按功能筛选可合并的启用角色，具体规则见下节。未标记功能权限的内部调用保留角色并集语义；当前未增加跨请求数据范围缓存。

## 按功能授权与新表接入

HTTP 入口的 `@SaCheckPermission` 在校验通过后建立功能上下文，只合并拥有这些权限的启用角色。拥有其他报表功能的全量角色不会扩大当前业务编辑权限；OR 权限只包含当前用户实际拥有的分支。内部未标记功能权限的调用保留原角色并集，敏感业务应通过明确入口调用。

生成器自动识别 `tenant_id`、`dept_id`、`owner_id`，也可指定部门与所有者列。当前租户插件约定租户列为 `tenant_id`，不接受其他租户列名。归属字段不进入创建/更新 DTO，创建时取可信租户和登录用户，缺少部门身份时拒绝创建。生成的 `AccessConfiguration` 注册租户和数据范围规则；关闭数据范围仍保留租户过滤。启动表审计可以发现带租户列却未注册的表，但部门/所有者规则仍应在业务接入审查中检查。

生成服务检查更新/删除影响行数，避免查询后权限或状态变化造成无效写入。跨部门归属调整由明确业务接口校验，不能让通用生成 DTO 直接赋值。
