# 部署与运维路线

生产交付先准备可恢复的数据和配置，再启动服务、验证关键路径。镜像构建成功只是其中一步。

| 阶段 | 阅读内容 | 检查结果 |
| --- | --- | --- |
| 准备生产环境 | [配置清单](/operations/configuration) | 密码、密钥、端口与服务一致 |
| 首次启动 | [Compose 部署](/deployment) | 健康检查、登录、文件访问 |
| 升级 | [迁移流程](/guide/database/migrations) | 副本演练、V30、校验记录 |
| 扩为多节点 | [集群配置与验收](/operations/cluster) | 共享会话、幂等、实时票据 |
| 备份与回滚 | [恢复步骤](/operations/backup) | 新恢复库可用、文件和密钥齐全 |
| 日常故障 | [按症状排错](/operations/troubleshooting) | 明确故障层与证据 |

## 一次发布要保留什么

记录提交/镜像版本、数据库迁移版本、部署变量来源和验证结果。密钥单独保管，不能随发布说明公开。CI 的 delivery job 验证配置并构建镜像，目标服务器的网络、卷、对象存储与业务账号仍需实际冒烟。

## 文档网站独立部署

本站是静态网站，不需要启动业务后端。构建产物在 docs/.vitepress/dist，支持根路径和子路径；CDN、Nginx 或其他托管平台的接入见[文档站部署](/documentation-site)。当前没有自动绑定公网域名。
