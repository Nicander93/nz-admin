# 首次登录与最小验收

本页帮助你确认“能启动”之外的基础链路：登录身份、菜单授权、数据读取和退出均正常。

## 本地初始化账号

开发初始化默认租户编码为 `default`，用户名为 `admin`，密码为 `admin123`。这只适用于使用默认初始化设置的本地库。已有库中的密码不会因为修改初始化变量而覆盖。

生产首次创建管理员使用 `NZ_INITIAL_ADMIN_PASSWORD`，并应按[生产部署](/deployment)完成密钥与初始化配置。

## 一次完整检查

1. 登录后打开工作台，确认没有接口错误。
2. 打开用户、角色、菜单页面，核对菜单加载与查询。
3. 创建一个测试角色，只分配一组菜单与按钮；创建测试用户并关联角色。
4. 在独立浏览器会话登录测试用户，确认没有获授的菜单和按钮不出现。
5. 使用该用户调用未授权接口，确认后端也拒绝，不能仅以按钮隐藏作为通过。
6. 退出后刷新受保护页面，应回到登录；失效令牌不再获得业务数据。

普通角色还需要配置数据范围。有菜单和按钮权限却看到空列表，可能是数据范围为空，不一定是查询接口失效。见[角色与数据范围](/platform/security/data-scope)。

## 体验审批

后端先升级至 V30，并开启新引擎。管理员在流程中心创建“请假申请”用途的定义，选择一个普通审批人，保存后发布。申请人保存请假草稿并提交，审批人从待办办理。

验收时使用两个用户会话，确认申请人不能代替审批人操作；通过后申请列表显示已通过。若退回后修改再提交，应保留原审批快照和轨迹。完整步骤见[审批中心与请假申请](/platform/workflow/approval-center)。

## 常见结果

| 现象 | 先检查 |
| --- | --- |
| 账号密码正确但不能登录 | 租户编码、租户停用或到期、用户状态 |
| 页面缺失 | 模块开关、套餐菜单、角色菜单、组件路径 |
| 按钮缺失 | 对应按钮权限是否分配 |
| 列表为空 | 当前租户、功能对应角色的数据范围、记录归属 |
| 新流程入口不可用 | V30、引擎开关、设计权限 |

用测试账号检查完成后清理自己创建的数据，保留生产初始化账号与历史迁移。后续开发从[开发指南](/developer-guide)开始。
